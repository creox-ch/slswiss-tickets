## 1. Datenschutzerklärung — обязательная структура

За основу брать `frankenplatz/site/Legal.jsx` (§130+) — он уже правильно устроен.
Чего в нём не хватает, отмечено ❗.

1. **Кто отвечает** — юрлицо, адрес, email. Если назначен представитель в ЕС — тоже.
2. **Какие данные собираем** — по категориям, а не «ваши данные».
   ❗ Для нас доописать: результаты калькуляторов (финансовые сводки),
   психотесты, факт входа на мероприятие (`checked_in_at`).
3. **Зачем и на каком основании** — цель + основание для каждой цели
   (договор / законный интерес / закон / согласие).
4. **Кому передаём** — ❗ **поимённо**, а не «поставщики услуг»:
   > Payrexx AG (приём платежей, Швейцария) · Supabase (хостинг базы данных, ЕС) ·
   > Resend (отправка писем) · Vercel Inc. (хостинг сайта, США) ·
   > Google Ireland/LLC (Google Analytics, Google Workspace)
5. **Передача за границу** — какие страны, какие гарантии (SCC).
6. **Сроки хранения** — ❗ конкретно, по категориям (таблица из [`README.md`](README.md) §7).
7. **Cookies и аналитика** — ❗ назвать Google Analytics прямо и описать, как отозвать согласие.
8. **Права субъекта** — доступ, исправление, удаление, ограничение, возражение, отзыв согласия,
   переносимость (GDPR), жалоба в **EDÖB** (CH) или в надзорный орган своей страны (ЕС).
9. **Контакт для запросов** — конкретный ящик, который кто-то читает.
10. **Дата версии.**

Правило, которое стоит записать в голову: **текст политики и поведение сайта обязаны совпадать.**
Если в баннере написано «грузим аналитику только с согласия» — код должен делать ровно это
(у нас делает); если в политике не назван Google Analytics, а он стоит — это расхождение,
и именно такое расхождение находят первым.

## 2. DPA (Auftragsverarbeitungsvertrag) — что должно быть внутри

Нужен, когда **мы процессор**: Verein Atlas Integra, MOTO-ZÜRICH, любой внешний клиент.

- Стороны; кто контролёр, кто процессор
- Предмет, характер и цель обработки; **категории данных и субъектов**
- Срок действия
- Обработка **только по документированным указаниям** контролёра
- Обязанность конфиденциальности сотрудников/подрядчиков
- **TOMs** — приложением (взять [`TOMS.md`](TOMS.md))
- **Субпроцессоры**: список приложением ([`PROCESSORS.md`](PROCESSORS.md)) + порядок уведомления о новых
- Содействие контролёру в ответах на запросы субъектов
- **Уведомление контролёра об инциденте без промедления** (указать срок: 24 ч разумно)
- Аудит/предоставление доказательств
- Что происходит по окончании: **удаление или возврат** данных
- Трансграничная передача и гарантии (SCC + Swiss addendum)

⚠️ Отдельным абзацем — честно про общее хранилище: данные разных контролёров лежат
в одной базе `submissions` с логическим разделением по `source`. Лучше написать это
самим, чем чтобы это обнаружил их юрист.

## 3. Процедура запроса субъекта (Betroffenenanfrage)

**Срок:** GDPR — 1 месяц. revDSG — как правило 30 дней. Ориентироваться на **30 дней**.

1. Запрос приходит на `info@` / `main@` → фиксируем дату получения.
2. **Проверяем личность** — но не требуем лишнего: сверить адрес, с которого пишут,
   с адресом в базе обычно достаточно. Паспорт запрашивать не надо.
3. Собираем данные по всем местам: `submissions`, `tickets`, ящики Google Workspace,
   логи Resend. ❗ Не забывать про почту — там чаще всего и лежит основной массив.
4. Отвечаем: выгрузка + перечень получателей + сроки хранения + источник данных.
5. При запросе удаления: удаляем, **кроме** того, что обязаны хранить по закону
   (бухгалтерия по оплаченным билетам — 10 лет). Об исключении сообщаем прямо.
6. Записываем в журнал: кто, когда, что сделали.

Заготовки SQL (выполнять осознанно, `service_role`):

```sql
-- 1. Что у нас есть на человека
select id, created_at, source, form_key, name, email, phone, telegram, status, consent
from public.submissions where lower(email) = lower('…');

select id, created_at, event_name, buyer_name, buyer_email, status, paid_at, checked_in_at
from public.tickets where lower(buyer_email) = lower('…');

-- 2. Обезличивание вместо удаления там, где строку надо сохранить для отчётности
update public.submissions
set name = null, email = null, phone = null, telegram = null,
    payload = '{}'::jsonb, tests = null, status = 'archived'
where lower(email) = lower('…');
```

## 4. Процедура на инцидент (Datensicherheitsverletzung)

**Срок:** revDSG — уведомить EDÖB «как можно скорее»; GDPR — **72 часа**. Работаем по 72 часам.

1. **Зафиксировать время обнаружения** — с него идёт отсчёт.
2. **Остановить утечку**: отозвать ключ, закрыть роут, снять деплой. Сначала остановить, потом разбираться.
3. **Оценить**: какие данные, сколько человек, есть ли особо ценные, есть ли риск для людей.
4. **Уведомить контролёра** (если мы процессор) — в течение 24 часов, даже с неполной картиной.
5. **EDÖB** — если есть риск для личности субъектов. Форма на сайте EDÖB.
6. **Уведомить людей** — если риск высокий (например, утекли финансовые расчёты с именами).
7. **Записать всё**: что случилось, когда, что сделали, что изменили, чтобы не повторилось.
   Этот журнал сам по себе — обязательный документ.

Ключи, которые придётся ротировать при подозрении на компрометацию (все — в env Vercel):
`SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `PAYREXX_API_SECRET`,
`PAYREXX_WEBHOOK_SIGNING_KEY`, `CRON_SECRET`, `CHECKIN_STAFF_KEY`.

## 5. Формулировка согласия на форме

Сейчас на формах стоит галочка согласия (без неё сервер возвращает 400 — это правильно).
Чего не хватает: **сохранения того, с какой формулировкой человек согласился**.

Минимальный текст рядом с чекбоксом:

> Я согласен(на) на обработку моих данных для ответа на эту заявку.
> Подробнее — в [политике конфиденциальности](/datenschutz). Согласие можно отозвать в любой момент.

Для рассылки — **отдельная** галочка (не «в комплекте» с заявкой):

> Хочу получать письма о форуме. Отписаться можно из любого письма.

Для психотестов на chudina — **третья**, отдельная:

> Я согласен(на) на обработку результатов тестов для оценки моей кандидатуры в команду.

Техническая доработка: писать в `submissions` версию текста согласия
(например `consent_version: 'v1-2026-08'`) — тогда через год будет чем доказать,
на что именно человек соглашался.
