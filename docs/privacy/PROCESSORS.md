# Реестр поставщиков (процессоров и субпроцессоров)

> Составлен 2026-08-06 по коду и по API Supabase. Колонка **DPA** заполнена честно:
> ❓ означает «я этого не проверял», а не «нет». Проверка требует захода в кабинеты
> сервисов — это делает Иванна, агенту туда нельзя (секреты и договоры).
>
> Правило: строка считается закрытой, когда в колонке DPA стоит ✅ + дата + где лежит подписанный/принятый документ.

## Инструменты разработки и работы (данные могут туда попадать)

| Инструмент | Риск | Что сделать |
|---|---|---|
| **Claude Code + Supabase MCP** | у агента при разработке права **service_role** к боевой БД с реальными 34 заявками и 3 билетами | Внутреннее правило: агенту не выгружать строки с персданными без явной необходимости; для отладки — тестовые данные или выборки без `email/name/payload`. Anthropic в этом сценарии — фактический субпроцессор |
| **GitHub (репо public)** | код открыт | ✅ секретов в репо нет (проверялось ранее). Держать это инвариантом: никаких дампов БД, скриншотов с email, тестовых строк с реальными адресами |
| **Trello / Miro / Google Drive** (подключены как коннекторы) | ❓ попадают ли туда персданные клиентов/участников | Проверить: если в карточках/досках лежат email и заявки — это ещё процессоры, и их надо внести в этот реестр и в политику |
| **GitHub Pages** (MOTO-ZÜRICH) | хостинг клиентского сайта | Если сайт клиентский — Creox процессор, нужен DPA **с клиентом** |

## Пока НЕ используются (проверено — не выдумывать в политике)

По результатам поиска в коде сайтов на 2026-08-06 **не найдено**: Typeform, Calendly,
Hotjar, Meta Pixel, Yandex.Metrica, Microsoft Clarity, встроенных YouTube/Vimeo,
Make/n8n/Zapier, OpenAI в рантайме.

Оговорка: это поиск по подстрокам в локальных копиях сайтов — инструмент грубый.
Если какой-то из сервисов подключался руками через кабинет (например, тег в GTM или
скрипт, добавленный после последней выгрузки дизайна), поиск по файлам его не увидит.
Перед подписанием любого документа для клиента список сверять ещё и по кабинетам.
