# TOMs — технические и организационные меры защиты

> Приложение к DPA и к политикам конфиденциальности. Отличие этого файла от типового
> «мы серьёзно относимся к безопасности» — **каждый пункт указывает на строку кода**,
> которую можно открыть и проверить. Сверено с кодом 2026-08-06.
>
> Раздел «Чего пока нет» — не признание слабости, а честная часть документа:
> клиент в Швейцарии скорее оценит прямой список, чем обнаружит дыру сам.

## 1. Контроль доступа к данным

| Мера | Как реализовано |
|---|---|
| База закрыта от браузера | RLS включён на `tickets` и `submissions`, **ни одной policy для anon/authenticated** — `supabase-schema.sql:66,108`. Весь доступ — только server-side через `service_role` |
| anon-ключ не используется вообще | В статических сайтах нет ключей Supabase; они ходят только в `POST /api/forms` |
| Ключ `service_role` — только на сервере | `lib/supabase.js`, ленивая инициализация; ключ живёт в env Vercel, в репо его нет (репо public) |
| Снят лишний грант TRUNCATE | `revoke truncate ... from anon, authenticated` — `supabase-schema.sql:114`. RLS не фильтрует TRUNCATE, поэтому убран отдельно |
| Служебная функция закрыта от REST | `revoke execute on function assign_forum_ticket_no from public, anon, authenticated` — `supabase-schema.sql:61` |
| Инвариант доступа закреплён тестом | `tests/pgtap/rls_access.sql` — проверяет, что RLS включён и грантов нет |
| Чек-ин требует ключа персонала | `CHECKIN_STAFF_KEY` → заголовок `X-Staff-Key` в `app/api/checkin/route.js` |
| Cron-роут не открыт наружу | `/api/cron/newsletter-digest` без `CRON_SECRET` отдаёт **503, а не открытый список** — env-комментарий в `.env.example:34-37`. Он выдаёт email подписчиков, поэтому fail-closed |

## 2. Законность сбора

| Мера | Как реализовано |
|---|---|
| Без согласия данные не сохраняются | `app/api/forms/route.js:109` — 400 «Нужно согласие на обработку данных», запись не создаётся |
| Момент согласия фиксируется | `submissions.created_at` = момент отправки формы с галочкой (`supabase-schema.sql:98-99`) |
| Double opt-in на рассылку | Одноразовый токен → `status='pending'` → подтверждение по ссылке → `confirmed` (`app/api/forms/route.js:127-132`, `/api/forms/confirm`) |
| Отписка в один клик | Заголовки `List-Unsubscribe` + `/api/forms/unsubscribe`; статус `unsubscribed` |
| Аналитика только по согласию | `frankenplatz/site/cookie-consent.js` — GA подключается **после** «Принять»; при отказе скрипт Google не грузится вообще. На chudina — Google Consent Mode v2, всё `denied` по умолчанию |
| Клиент не диктует текст писем | Содержимое отчётов и подтверждений собирает сервер из сохранённого `payload` (`lib/forms.js`) — иначе эндпоинт стал бы спам-релеем от нашего домена |

## 3. Минимизация и защита от мусорных данных

| Мера | Как реализовано |
|---|---|
| Жёсткий Origin-чек | `app/api/forms/route.js:87` — POST принимается только с доменов белого списка. CORS ограничивает браузер, но не curl |
| Белый список не может стать пустым | Кривая env из одних запятых откатывается на `DEFAULT_ORIGINS` (`lib/forms.js:36-46`) — иначе приём заявок ложится целиком |
| Honeypot | Скрытое поле заполнено → отвечаем «ок», в базу не пишем (`route.js:101`) |
| Time-trap | Форма «заполнена» быстрее 2500 мс → бот, не пишем (`route.js:104`, `MIN_FILL_MS`) |
| Ограничение размера | Одно поле ≤ 2000 символов, весь `payload` ≤ 20000 (`lib/forms.js:13-14`) — защита от заливки мусора в БД |
| Служебные поля не сохраняются | `hp`, `elapsed_ms`, `send_report` отбрасываются перед insert (`route.js:117`) |

## 4. Платежи

| Мера | Как реализовано |
|---|---|
| Данные карты к нам не попадают | Оплата на стороне Payrexx (Gateway), мы храним только сумму и `payrexx_tx_id` |
| Цену определяет сервер | `TICKET_PRICE_RAPPEN`; `amount` из тела запроса игнорируется — клиент не может купить билет за 0.01 CHF |
| Подпись вебхука fail-closed | Без `PAYREXX_WEBHOOK_SIGNING_KEY` вебхук **отклоняется** (`lib/payrexx.js`, `app/api/payrexx/webhook/route.js`) |
| Не доверяем payload вебхука | После приёма — независимый `GET /Transaction/{id}` и проверка `status === 'confirmed'` |
| Оплата не теряется молча | Наша ошибка → HTTP 500 → Payrexx ретраит; обработка идемпотентна |
| Гонка сканеров безопасна | `update ... eq(status,'paid').select()` — проигравший получает `already`, а не второй «вход» |

## 5. Защита от инъекций и утечек через письма

| Мера | Как реализовано |
|---|---|
| Экранирование пользовательского ввода | `escapeHtml` во всех письмах (`lib/ticket.js`, `lib/forms.js`), покрыто unit-тестом |
| QR-роут не принимает произвольное | `/api/qr` берёт только токеноподобный `t`: 8–64 символа `[A-Za-z0-9_-]` |
| Сканер не делает авто-checkin из URL | `/scan` отмечает только через камеру или ручной ввод — покупатель не отметит сам себя |
| Ошибка письма не роняет запись | Заявка/билет сохраняются, даже если Resend недоступен (везде try/catch + `console.error`) |

## 6. Процесс разработки

| Мера | Как реализовано |
|---|---|
| Branch protection на `main` | Оба репо creox-ch: PR + 1 ревью для не-админов |
| CI на каждый PR | `.github/workflows/test.yml` — build + Playwright (unit + e2e) |
| Изменения оплаты/форм — только через PR | Внутреннее правило по риску проекта |
| Dev-бэкдоры удалены | `app/api/dev/issue` (выпускал оплаченный билет без оплаты) удалён 2026-07-12; диагностический GET с кусками секретов — тоже |
| Секреты вводит человек | API-ключи и токены в кабинеты вводит Иванна, не агент |

## 7. Чего пока нет (перечислять честно)

| Пробел | Риск | Приоритет |
|---|---|---|
| **Нет автоматического удаления данных** — ни ретенции, ни очистки `pending`-билетов | Данные копятся бессрочно; прямое расхождение с обещанием «храним столько, сколько нужно» в политике форума | 🔴 |
| Нет процедуры на запрос субъекта (доступ/удаление) | Ответ придётся собирать вручную под давлением срока | 🟡 |
| Нет процедуры на инцидент/утечку | revDSG требует уведомить EDÖB как можно скорее — без плана этот срок теряется | 🟡 |
| Нет бэкап-политики своими руками | Полагаемся на автобэкапы Supabase — ❓ проверить их глубину на текущем плане | 🟡 |
| Нет журнала доступа к персданным | Кто и когда смотрел `submissions` — не фиксируется | 🟢 |
| Нет 2FA-политики на аккаунты | ❓ проверить, включена ли 2FA на GitHub, Vercel, Supabase, Google, Payrexx, Resend | 🟡 |
| Не проверено, что попадает в логи Vercel | `console.error` может выносить содержимое ошибок с email | 🟡 |
| Один общий Supabase на разных контролёров | `atlasintegra` (Verein) и данные форума лежат в одной таблице | 🔴 юридически, 🟢 технически |
